# Map Components

This module provides shared components for displaying Locations and Routes on Geoapify + MapLibre maps.

The module's objective is to keep map concerns decoupled from APIs and business flows. External containers are responsible for calling the backend, checking user roles, opening forms, and handling mutations.

## Features

- Render MapLibre maps with Geoapify styles.
- Pan, zoom, reset view, and fit bounds.
- Render multiple Location markers.
- Skip locations with invalid coordinates.
- Hover marker to open Location popup.
- Popup auto-closes after 3 seconds when hover ends.
- Popup stays open when moving cursor from marker into popup.
- Popup is positioned cleanly below the search bar without triggering unexpected map shifts.
- Location search with 300ms debounce.
- Click location in search results to fly to marker.
- Select From/To when creating a Route using a searchable picker with 300ms debounce.
- Map click returns `{ latitude, longitude }`.
- Add Location mode finds nearby POIs within a 10km radius.
- Nearby POIs directly use name, address, and coordinates from Places response.
- Exact clicked point uses Reverse Geocoding to suggest an address.
- Render Routes using GeoJSON `LineString` or `MultiLineString`.
- Render multiple routes via `routes`, maintaining backwards compatibility with `route`.
- Unified modes: `view`, `addLocation`, `addRoute`, `buildPlan`.
- Geoapify route preview with abort, timeout, and estimated distance/duration.
- Add/Edit Location form with validation.
- Route form with validation ensuring From and To do not match.
- Display Edit/Delete buttons according to callbacks and permissions passed by container.
- Geoapify search and reverse geocoding utilities.
- MapLibre worker uses the URL generated by Vite without hard-coded URLs.

## Pending Backend / API Contract Features

The current API contract documents read APIs:

- `GET /api/v1/locations`
- `GET /api/v1/routes`

Therefore, the module does not directly invoke mutations for the following actions:

- Add/Edit/Delete Location.
- Create/Edit/Delete Route.
- Save Route geometry.
- Call Geoapify Routing and persist distance/duration.

Forms emit payloads via `onSubmit`. When the backend adds these endpoints, containers/services can wire the mutations.

## Usage Example

```tsx
import { useMemo, useState } from "react";
import { MapViewer, type MapLocation } from "@/shared/components/map";

export function LocationMap({ locations }: { locations: MapLocation[] }) {
  const [search, setSearch] = useState("");

  const options = useMemo(() => {
    const query = search.trim().toLowerCase();
    if (!query) return locations;

    return locations.filter((location) =>
      [location.name, location.city, location.country]
        .filter(Boolean)
        .some((value) => value!.toLowerCase().includes(query)),
    );
  }, [locations, search]);

  return (
    <MapViewer
      locations={locations}
      showSearch
      searchOptions={options}
      onSearchChange={setSearch}
      onLocationSelect={(location) => {
        console.log("Selected location", location);
      }}
      onMapClick={(point) => {
        console.log("Map point", point);
      }}
    />
  );
}
```

## `MapLocation`

```ts
type MapLocation = {
  id: string | number;
  name: string;
  type?: string | null;
  country?: string | null;
  address?: string | null;
  city?: string | null;
  stateProvince?: string | null;
  latitude: number;
  longitude: number;
  note?: string | null;
};
```

Mapping from backend responses should reside in the container/service:

```ts
const location: MapLocation = {
  id: apiLocation.locationId,
  name: apiLocation.locationName,
  type: apiLocation.locationType,
  address: apiLocation.address,
  city: apiLocation.city,
  stateProvince: apiLocation.stateProvince,
  country: apiLocation.country,
  latitude: Number(apiLocation.latitude),
  longitude: Number(apiLocation.longitude),
  note: apiLocation.locationNote,
};
```

## Key Callbacks

| Callback           | Trigger Condition                        |
| ------------------ | ---------------------------------------- |
| `onLocationSelect` | User selects marker or search option     |
| `onLocationHover`  | User hovers on or leaves marker          |
| `onMapClick`       | User clicks a point on the map           |
| `onMarkerAction`   | User clicks Edit/Delete in popup         |
| `onRouteSelect`    | User clicks Route line                   |
| `onSearchChange`   | Debounced search input changed           |

`MapViewer` does not call API mutations or check roles directly. The container provides permissions:

```tsx
<MapViewer
  canEditLocation={isCoordinator}
  canDeleteLocation={isCoordinator}
  onMarkerAction={(action, location) => {
    if (action === "EDIT") openEditForm(location);
    if (action === "DELETE") openDeleteConfirm(location);
  }}
/>
```

## Route GeoJSON

Pass the backend geometry through `routeGeoJson`:

```tsx
<MapViewer
  locations={locations}
  route={{ id: route.routeId, name: route.routeName }}
  routeGeoJson={route.geometry}
/>
```

The module only validates and renders geometry. It does not recompute distance/duration to send to backend.

## Geoapify

`.env` requires:

```env
VITE_GEOAPIFY_API_KEY=your-key
```

Utilities:

```ts
import {
  createGeoapifyMapStyleUrl,
  reverseGeocodeGeoapify,
  searchGeoapifyPlaces,
} from "@/shared/utils/map";
```

Add Location nearby search uses specific categories within a 10km radius:

```ts
const nearbyCategories = [
  "populated_place.city",
  "airport",
  "commercial.port",
  "service.vehicle",
];
```

The POI selection flow does not call extra APIs. Only the `Use exact clicked point` flow invokes Reverse Geocoding.

Do not hard-code API keys in source code. Geoapify Routing preview is used for interaction only; it does not replace official distance/duration from the backend.

## Whitebox Testing

In a development environment, open:

```text
http://localhost:5173/__dev/map
```

Test page features:

- Log in via backend with various roles.
- Call `GET /locations` using a real access token.
- If backend returns no locations, display empty/error state from API without fallback data.
- Display data source as `BE` or `MOCK`.
- Coordinator can access Add Location and Create Route actions.
- Other roles have read-only access.

Mutations in whitebox test display payloads via toast notifications without making network requests until backend endpoints are available.

Utilities located in `src/shared/utils/map/`:

- `coordinates.ts`: Parse and validate coordinates.
- `bounds.ts`: Calculate bounds from Location/Route.
- `geojson.ts`: Validate and normalize GeoJSON.
- `geoapify.ts`: Style URL, search, and reverse geocode.
